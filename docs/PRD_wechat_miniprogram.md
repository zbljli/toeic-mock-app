# TOEIC Coach 微信小程序 — 产品需求文档 (PRD)

> **版本:** v1.0
> **状态:** 草案
> **目标上线:** TBD
> **目标用户规模:** 1 万 DAU
> **平台:** 微信小程序 (原生 / Taro / uni-app，技术选型 TBD)

---

## 1. 产品概述

### 1.1 产品定位

TOEIC Coach 是一款**面向中国托业备考人群的 AI 驱动型智能学习工具**，以微信小程序为载体，提供全套托业听力+阅读模考、专项训练、能力诊断与个性化学习推荐。产品核心竞争力在于**零门槛启动**（无需下载安装、无需注册登录）与 **AI 驱动的自适应学习路径**。

### 1.2 目标用户

- **大学生（主力人群）:** 大三/大四学生，TOEIC 成绩用于求职（尤其是日韩企业、外企）、保研、出国交换。英语基础四级以上，对托业题型不熟悉。
- **职场新人（1-3 年经验）:** 入职后公司要求 TOEIC 分数用于定岗、晋升或海外派遣。时间碎片化，需要高效备考工具。
- **英语学习爱好者:** 无明确考试 deadline，希望通过托业体系化提升商务英语能力。

### 1.3 核心价值主张

| 痛点 | 解决方案 |
|------|----------|
| APP 下载门槛高，用户懒得装 | 微信小程序零安装，扫码 / 搜索即用 |
| 注册流程繁琐，流失率高 | wx.login 静默登录，打开即用，无需填手机号 |
| 不知道自己的水平 & 弱点 | 智能诊断测试 → 能力雷达图 → 精准定位薄弱 Part |
| 不知道从哪学起 | AI 教练生成个性化学习推荐 + 每日任务 |
| 独自备考孤独、难坚持 | 成长日记 + 社交分享（匿名排行榜、学习打卡） |
| 模考不方便 | 200 题全真模拟，计时+自动交卷，和真实考场一致 |

### 1.4 为什么是微信小程序

| 优势 | 产品层面的利用 |
|------|---------------|
| **零安装** | 扫码、搜索、群分享直接打开，获客成本极低 |
| **wx.login 静默登录** | Onboarding 全程无需跳出，打开即绑定 OpenID |
| **微信云开发** | 免运维后端，云函数 + 云数据库 + 云存储，适合 1 万用户规模快速验证 |
| **社交分享** | 成绩单分享到群/朋友圈 → 裂变获客；学习打卡 → 形成习惯 → 留存 |
| **模板消息** | 每日学习提醒、模考交卷通知，低成本促活 |
| **微信支付** | 未来付费订阅 / 单次购买的直接变现通道 |

## 2. 用户画像

### 2.1 Persona A: 求職大學生 小李

**基本信息:** 22 岁，大四，某 211 大学国际贸易专业
**英语水平:** CET-4 520 分，未接触过 TOEIC
**目标:** 2 个月内 TOEIC 750+，用于日企校招简历
**使用场景:**
- 每天晚上在宿舍用手机刷题 30-45 分钟
- 碎片时间（食堂排队、等公交）背单词
- 周末做一次完整模考
**痛点:**
- 不知道 TOEIC 和四六级有什么区别
- 听力 Part 3-4（对话和独白）完全跟不上
- 一个人在宿舍学很难坚持

**Journey:**
1. 在年级群里看到同学分享的"TOEIC 模考成绩单"小程序卡片 → 点击打开
2. 小程序自动静默登录 → 进入 Onboarding
3. 看到成功故事（"30 天从 450 到 780 的学长"）→ 有信心了
4. 设定目标分数 750 → 完成 15 分钟诊断测试
5. 能力报告显示：Part 2（应答问题）正确率 30%，Part 5（句子填空）正确率 60%
6. AI 教练推荐：「本周重点攻克 Part 2 — 疑问词识别训练」
7. 每天完成推荐任务（15min），周末做一次模考
8. 一周后 Part 2 正确率提升到 55%，生成成长卡片分享到宿舍群

## 3. 功能清单

### 3.1 优先级定义

| 优先级 | 定义 | 判断标准 |
|--------|------|----------|
| **P0** | MVP 必须上线 | 没有它产品核心闭环不成立，用户无法完成"模考→出分→看解析"的最小路径 |
| **P1** | 上线后首个迭代 | 提升留存和体验的核心功能，用户强烈期待 |
| **P2** | 后续迭代 | 锦上添花，差异化竞争或变现功能 |

### 3.2 P0 — 核心功能（MVP）

| # | 功能 | 一句话描述 |
|---|------|-----------|
| P0-1 | **wx.login 静默登录** | 用户打开小程序即自动通过微信登录，无需手动输入任何信息，后端通过 wx.login 获取 OpenID 创建用户档案。 |
| P0-2 | **Onboarding 流程** | 首次用户经过「欢迎页 → 成功故事 → 目标设定 → 诊断测试（可选 5 题/100 题/跳过）→ 能力报告」的引导流程，完成用户画像初始化。 |
| P0-3 | **全真模考** | 100 题听力模拟考试，Part 1-4 (45min)，真实计时+倒计时+自动交卷。**不做 Reading (Part 5-7)**。 |
| P0-4 | **分 Part 专项练习** | 支持选择任意听力 Part (1-4) 独立练习，自定义题数，做完即时出分。 |
| P0-5 | **智能评分** | 基于 TOEIC 原始分→转换分标准模型，输出 5-495 分制听力分数。 |
| P0-6 | **答题卡 & 计时器** | 模考中显示全局答题卡支持快速跳转、标记疑问题；Part 级别倒计时 + 全局倒计时。 |
| P0-7 | **成绩展示** | 模考/练习完成后展示总分、分 Part 正确率、用时，以可视化图表呈现。 |
| P0-8 | **答案解析 & 错题回顾** | 逐题查看正确答案 vs 用户答案，听力题附带 transcript 文本。 |
| P0-9 | **成绩历史** | 按时间倒序列出所有模考/练习记录，点击可进入成绩详情和错题回顾。 |
| P0-10 | **音频播放（听力）** | 支持 Part 1-4 的音频播放，每题可单独播放、支持重播（受限于微信小程序音频 API：需用户手势触发首次播放，支持后台播放）。 |

### 3.3 P1 — 增长 & 留存功能

| # | 功能 | 一句话描述 |
|---|------|-----------|
| P1-1 | **AI 教练首页** | 基于诊断测试结果展示能力雷达图、薄弱 Part 提示、今日推荐学习任务列表。 |
| P1-2 | **智能学习推荐** | 根据用户薄弱点和目标分数，自动生成分阶段（基础巩固→重点突破→冲刺提升）的学习计划。 |
| P1-3 | **场景学习** | 按商务场景（会议、谈判、邮件、出差、面试等）分类的听力文章，配有音频+原文+理解题。 |
| P1-4 | **词汇 Dashboard** | 展示按场景/Part 分类的托业高频词汇列表，标注用户掌握程度（未学/学习中/已掌握）。 |
| P1-5 | **词汇 Quiz** | 选择题形式的单词测试，支持「看英文选中文」「看中文选英文」「听音选词」三种模式。 |
| P1-6 | **词汇 Wiki** | 每个单词的详情页：释义、例句、词根词源、同义词辨析、发音音频。 |
| P1-7 | **语法 Wiki** | 托业核心语法点（时态、语态、从句、虚拟语气等）的结构化知识库。 |
| P1-8 | **语法 Quiz** | 选择题形式的语法测试，每题附带知识点解析。 |
| P1-9 | **成长日记** | 用户每日记录学习心得、难点、明日计划，自动关联当日学习数据（正确率、学习时长、完成题数）。 |
| P1-10 | **成绩单社交分享** | 模考完成后一键生成成绩单卡片图片，支持分享到微信群/朋友圈（隐去敏感信息选项），附带小程序码引导新用户扫码。 |
| P1-11 | **学习提醒（模板消息）** | 用户授权后可收到每日学习提醒推送、模考交卷提醒、周报总结。 |

### 3.4 P2 — 差异化 & 变现功能

| # | 功能 | 一句话描述 |
|---|------|-----------|
| P2-1 | **错题本** | 自动收集模考和练习中的错题，支持按 Part / 错误类型分类复习、重做错题。 |
| P2-2 | **能力趋势图** | 按时间维度展示分数变化趋势、各 Part 正确率变化曲线，帮助用户直观看到进步。 |
| P2-3 | **学习排行榜** | 匿名（可自选是否匿名）展示本周学习时长/正确率排名，利用社交激励提升活跃度。 |
| P2-4 | **社区故事** | 用户可匿名发布自己的备考故事和进度，其他人可点赞/评论，形成轻量学习社区。 |
| P2-5 | **付费会员** | 通过微信支付开通月度/季度/年度会员，解锁高级功能：无限制模考、AI 深度分析报告、专属学习计划。 |
| P2-6 | **模拟真实考场模式** | 完全还原 TOEIC 正式考试流程，包括考前说明音频、答题卡填涂模拟、Part 间不可逆。 |
| P2-7 | **离线缓存** | 缓存题库和音频到本地，支持无网络环境下模考（评测结果联网后同步）。 |

## 4. Onboarding 流程

### 4.1 设计目标

1. **零摩擦进入:** 用户从点击进入到开始学习，整个流程 < 3 分钟
2. **静默登录:** 在欢迎页渲染前完成 wx.login → 后端换取 OpenID → 创建/查找用户档案，用户全程无感知
3. **灵活诊断:** 提供 5 题快速版 / 100 题完整版 / 跳过三种诊断方式，适配不同耐心水平的用户
4. **即时价值:** Onboarding 结束时立刻展示能力报告 + 第一个学习推荐，让用户感受到"这东西有用"

### 4.2 完整流程

```
用户打开小程序

     ▼
┌──────────────────────┐
│ Step 0: 静默登录      │  ← wx.login() → 后端 → 创建/查找 User Profile
│ (用户无感知, < 500ms) │     获取 openid, unionId (如有)
└──────────────────────┘

┌──────────────────────┐

     │
     ▼

└──────────────────────┘
     │
```

### 4.3 技术实现要点

| 步骤 | 关键实现 | 备注 |
|------|---------|------|
| Step 0 | `wx.login()` 获取临时 code → 发送到后端云函数 `user/login` → 调用 `auth.code2Session` 换取 OpenID → 查数据库有无此用户 → 有则读取档案，无则创建 | 利用微信云开发免鉴权特性，云函数天然可获取 `wxContext.OPENID` |
| Step 2 | 成功故事数据从云数据库读取（支持运营后台动态更新） | 首次加载默认展示 3 个硬编码故事作为兜底 |
| Step 3 | 目标数据写入 `userGoal` 字段 | 选择「我只是想学学」的用户跳过分数诊断，直接进入自由浏览模式 |
| Step 4 | 诊断测试复用 P0-4「分 Part 练习」的引擎，限定 Part 1-7 各 1 题（5 题版）或 Part 1-7 按比例抽样（100 题版） | 5 题版诊断精度低但完成率高；100 题版诊断精度高但流失率高 |
| Step 5 | 诊断结果调用评分引擎 → 生成 `AbilityProfile` → 调用推荐引擎生成第一条 `LearningRecommendation` → 写入数据库 | 能力雷达图用 Canvas 2D API 在小程序端绘制 |

### 4.4 异常处理

| 场景 | 处理方式 |
|------|---------|
| 用户在 Step 2-4 中途退出小程序 | 下次打开时恢复到最后停留的步骤（进度存储于云数据库 `onboardingStage` 字段） |
| wx.login 失败 | 降级为仅本地存储模式，Onboarding 正常走完，数据暂存本地，网络恢复后同步 |
| 用户选择「跳过」诊断测试 | 基于目标分数生成一个保守的初始能力画像（各 Part 正确率设为 40-50%），后续随着模考数据积累自动修正 |
| Onboarding 再次进入（已完成过的用户） | 直接跳转 AI 教练首页，右上角提供「重新诊断」入口 |

## 6. 关键指标

### 6.1 北极星指标

> **「每周完成至少 1 次有效学习 session 的用户数」**

定义「有效学习 session」为：完成一次模考（任意题数），或完成一次专项练习（>= 5 题），或完成一幕场景学习文章（含理解题）。

**选择理由:** TOEIC 备考是持续性行为，单纯的「注册用户数」或「DAU」无法衡量产品是否真正在解决用户问题。用户只有持续做题、持续看到分数提升，才会认可产品价值并形成习惯。

### 6.2 关键产品指标

| # | 指标 | 定义 | 目标值（上线 3 个月） |
|---|------|------|---------------------|
| K1 | **Onboarding 完成率** | 完成 Onboarding 全部 5 步 / 打开小程序的独立用户数 | >= 60% |
| K2 | **首次模考发起率** | Onboarding 完成后 7 天内发起至少 1 次模考的用户占比 | >= 50% |
| K3 | **模考完成率** | 完成模考（自动交卷或主动交卷）/ 发起模考次数 | >= 80% |
| K4 | **D7 留存率** | 首次使用后第 7 天仍回访的用户占比 | >= 30% |
| K5 | **D30 留存率** | 首次使用后第 30 天仍回访的用户占比 | >= 15% |
| K6 | **周活跃学习用户数** | 每周完成 >= 1 次有效学习 session 的独立用户数 | 北极星指标，持续追踪 |
| K7 | **分享率** | 成绩单分享 / 模考完成次数 | >= 10% |
| K8 | **平均学习时长** | 每用户每周在小程序内的累计学习时长（分钟） | >= 60 min/周 |

### 6.3 辅助观测指标

- **5 题 vs 100 题诊断选择比例:** 评估用户耐心水平，指导产品节奏优化
- **各 Part 练习分布:** 评估题库覆盖是否满足需求，识别高频薄弱 Part
- **小程序启动来源分布:** 搜索 / 群分享 / 小程序列表 / 公众号，指导获客渠道投放
- **音频播放成功率:** 监控微信环境兼容性（iOS / Android 差异）
- **静默登录成功率:** 监控 wx.login + 后端换 OpenID 的链路稳定性

## 7. 验收标准 (P0)

### P0-1: wx.login 静默登录

- [ ] 用户首次打开小程序，无任何弹窗和输入框，2 秒内进入欢迎页
- [ ] 后端成功获取 OpenID 并创建/查找用户档案
- [ ] 同一微信用户多次打开，档案不重复创建
- [ ] wx.login 失败时降级为本地存储模式，不阻塞 Onboarding 流程
- [ ] 网络恢复后本地数据自动同步到云端

### P0-2: Onboarding 流程

- [ ] 新用户依次看到欢迎页 → 成功故事 → 目标设定 → 诊断测试选择 → 能力报告
- [ ] 用户在中途退出，下次打开恢复到退出时的步骤
- [ ] 「5 题快速诊断」从选择到出报告 < 5 分钟
- [ ] 「跳过诊断」后基于目标分数生成合理的默认能力画像
- [ ] Onboarding 完成率 >= 60%（上线后以实际数据验证）
- [ ] 已完成的用户再次打开直接进入首页，不再重复 Onboarding

### P0-3: 全真模考

- [ ] 200 题按 TOEIC 标准 Part 1-7 结构呈现（6+25+39+30+30+16+54）
- [ ] 听力 Part 1-4 每道题音频自动播放，每题只播放一遍（与真实考试一致）
- [ ] 阅读 Part 5-7 可自由前后翻题，答题卡支持快速跳转
- [ ] 全局计时器正确运行，120 分钟倒计时归零时自动交卷并保存已作答题目
- [ ] 听力部分和阅读部分之间有明确的分界提示（V2 考场模式）
- [ ] 模考完成率 >= 80%（交卷/发起）

### P0-4: 分 Part 专项练习

- [ ] 7 个 Part 逐一可选
- [ ] 用户可自定义练习题数（默认 10 题，范围 5-50）
- [ ] 练习无强制计时限制，用户可随时退出
- [ ] 练习完成后即时展示正确率 + 用时
- [ ] 听力 Part 支持音频播放

### P0-5: 智能评分

- [ ] 正确输出 5-495 分制的听力和阅读分数
- [ ] 正确输出 10-990 分制的总分
- [ ] 分 Part 统计正确题数和正确率
- [ ] 评分逻辑与 TOEIC 官方评分表对标（误差 < 5 分）

### P0-6: 答题卡 & 计时器

- [ ] 模考中可随时调出答题卡浮层，查看全部题目作答状态（已答/未答/标记）
- [ ] 点击答题卡任意题号可直接跳转
- [ ] 支持对题目标记「疑问」（后期回顾时重点关注）
- [ ] 计时器在页面所有区域持续可见（悬浮或顶部固定）
- [ ] 最后 5 分钟计时器变红闪烁提醒
- [ ] 计时归零后自动交卷，用户正在作答的那道题保留已选选项

### P0-7: 成绩展示

- [ ] 总分、听力分、阅读分数字清晰
- [ ] 分 Part 正确率以进度条或柱状图展示
- [ ] 显示总用时（mm:ss 格式）
- [ ] 与历史平均分 / 上次分数的对比（如有历史数据）

### P0-8: 答案解析 & 错题回顾

- [ ] 逐题可查看题目、用户选项、正确答案
- [ ] 正确选项绿色高亮，错误选项红色高亮
- [ ] 听力题附带 transcript 文本
- [ ] 阅读题原文中标注答案定位（高亮关键句）
- [ ] 支持左右滑动 / 上下题按钮切换题目

### P0-9: 成绩历史

- [ ] 按时间倒序列出所有模考/练习记录
- [ ] 每条记录显示：日期、类型（模考/练习）、Part（如适用）、分数/正确率、用时
- [ ] 点击记录进入对应的成绩详情 + 答案解析
- [ ] 支持左滑删除（带确认弹窗）

### P0-10: 音频播放

- [ ] 听力题音频在用户点击播放按钮后正常播放
- [ ] 支持单题重播（重播按钮点击后重新播放本题音频）
- [ ] iOS 和 Android 微信环境兼容
- [ ] 模考模式下每道听力题只播放一遍（真实考试规则），练习模式下可多次播放
- [ ] 音频加载失败时显示友好提示并提供「重试」按钮

## 8. 风险 & 假设

### 8.1 关键假设

| # | 假设 | 验证方式 | 验证时间 |
|---|------|---------|---------|
| H1 | **用户愿意在微信小程序中完成 120 分钟的全真模考**。假设小程序场景下用户不排斥长时间持续使用，与原生 App 行为无显著差异。 | 观测 P0-3 模考完成率，若 < 60% 考虑：(1) 增加中途休息提醒；(2) 拆分听力/阅读为可分开考的独立模考；(3) 调研退出原因。 | 上线后 2 周 |
| H2 | **5 题快速诊断足以生成有意义的初始学习推荐**。假设 5 题（每 Part 1 题）的诊断精度虽低但不影响用户对 AI 教练的信任感。 | 对比 5 题诊断用户的首周学习完成率 vs 100 题诊断用户，若无显著差异则假设成立；若差异大，考虑取消 5 题版或增加至 15 题。 | 上线后 1 个月 |
| H3 | **微信社交分享能带来显著的免费获客**。假设成绩单分享到群/朋友圈的转化率可达到「每 10 次分享带来 1-3 个新用户」。 | 观测分享率 + 分享带来的新用户占比。若分享率 < 5%，需要优化分享卡片设计、增加分享激励（如分享解锁额外模考次数）。 | 上线后 2 周 |
| H4 | **题库内容在小程序场景下不存在合规风险**。假设自研/授权题库内容能通过微信小程序审核，不被判定为「在线教育-学科类」而触发资质要求。 | 提交小程序审核前，先提交 1.0 版本（仅含核心模考功能）进行预审，观察审核反馈。准备 ICP 备案、教育类目资质作为 Plan B。 | 开发中期 |
| H5 | **微信云开发能满足 1 万 DAU 的性能要求**。假设云函数的冷启动延迟、数据库 QPS 限制在 1 万 DAU 规模下不会影响用户体验。 | 在开发阶段进行压力测试：模拟 1000 并发请求评测云函数响应时间和数据库读写延迟。若性能不足，考虑迁移到微信云托管（容器化）或自建后端。 | 开发后期 |

### 8.2 已知风险 & 缓解措施

| 风险 | 严重度 | 缓解措施 |
|------|--------|---------|
| **微信小程序音频 API 限制:** iOS 微信 WKWebView 对音频自动播放有严格限制，可能导致听力模考中自动进入下一题的音频无法自动播放 | 高 | 每题播放前使用 `wx.createInnerAudioContext()` 并在用户首次手势交互后建立音频上下文；模考中每道听力题结束采用「点击下一题」而非全自动跳转；提前在 iOS 微信多版本上充分测试 |
| **小程序包大小限制:** 微信小程序主包限制 2MB，分包总大小限制 20MB，题库 + 音频资源可能超出 | 中 | 题库 JSON 数据存放于云存储，按 Part 动态加载；音频文件使用云存储 CDN 链接，按需下载；小程序包内仅保留核心 UI 代码和少量兜底数据；使用分包策略按功能模块拆分 |
| **用户数据迁移成本:** 现有 Expo App 如有用户数据，后续若决定停更 App 版，需考虑用户迁移 | 低 | 初期双平台并行运营；小程序内提供「从 App 导入数据」的 Token 机制；长期通过微信 UnionID 实现跨平台数据打通 |
| **微信生态政策变化:** 微信可能随时调整小程序审核规则、模板消息额度、虚拟支付政策 | 中 | 关注微信开放社区公告；模板消息作为促活手段而非核心功能（无模板消息时用户仍可正常使用）；虚拟支付预留 H5 支付兜底方案 |
